# YUTO 悠途

面向银发旅行者的目的地探索与行程工具。项目从空目录建立，采用 Python 3.9+、SQLite 和无需构建的 JavaScript 前端。

## 原生 iOS App

在 Mac 的 Xcode 中打开 `YUTO.xcodeproj`，选择 `YUTO` scheme 和一台 iPhone 模拟器，按 ⌘R。最低系统 iOS 17，支持 iPhone 和 iPad。真机调试需在 Signing & Capabilities 里选择自己的开发团队。

SwiftUI App 自带离线景区目录，提供首页、发现、行程、我的四个原生导航页。旅行画像、收藏和行程保存在当前设备，支持系统动态字体、放大字号以及原生分享。“银发友好度待确认”表示目前没有足够的证据算出总分。

更新数据库后，运行 `python3 -B iOS/export_catalog.py`，再构建 App。导出时会保留公开的景区信息，排除内部来源和采集日志。当前 App 使用本地规则，在线模型、账户同步、实景图库与在线地图仍待接入。

命令行构建验证：

```sh
xcodebuild -project YUTO.xcodeproj -scheme YUTO -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

### 原生界面与验收

新版以白底、黑色文字和实景摄影为主。首页将搜索与重点景区放在首屏，透明底 3D 地貌图用于点亮入口，进度来自已完成行程。发现页以 31 个省级地区的封面进入景区列表。精选的西湖、拙政园、鼓浪屿使用授权实景照片，其他省份封面使用电影感景观示意图。照片授权可在我的页面查看。景区详情单独展示真实游览条件，插画仅用于功能引导。筛选、收藏状态、行程编辑和个人设置都提供原生控件或文字反馈。

项目根目录已用官方 UI/UX Pro Max CLI 初始化 Codex 技能。主要界面采用系统字体、原生标签页、清晰的按压状态和可换行的布局。颜色和基础组件集中在 `iOS/DesignSystem`。

在 Xcode 选择可用的 iPhone 模拟器后，按 ⌘U 运行 `YUTOUITests`。流程覆盖搜索西湖、查看景区、收藏、保存计划、重启后恢复数据以及取消行程编辑。测试使用单独的本地数据域。

首页天气默认显示杭州，也可手动选择城市或主动授权定位。当前天气由 Open-Meteo 提供，公开端点用于开发预览。商业发布前应使用符合供应商条款的服务。AI 预估仅为三处精选景区的编辑初估，不参与个性化筛选或正式评分。

### iOS 工程结构

- `iOS/App`：应用入口、标签页与行程编辑导航、旅行状态。
- `iOS/Features`：首页、发现、景区详情、行程和个人画像，各自管理页面交互。
- `iOS/Domain`：景区、旅行画像与行程模型，以及独立于 SwiftUI 的匹配和规划规则。
- `iOS/Data`：离线目录加载、本地数据读写。沿用上一版的存储键，启动时为旧行程生成并保存每日安排。
- `iOS/DesignSystem`：共享颜色和页面布局。
- `iOS/Resources`：离线目录和品牌插画。
- `iOS/Tests`：无需模拟器即可运行的核心验收，执行 `bash iOS/Tests/run.sh`。

新行程保存时记录每日安排。修改旅行画像或只调整日期、出发城市及人数时，已保存的每日安排按原样显示。

## 辅助服务

数据采集、运营后台及模型接口继续使用本地 Python 服务。iOS App 本身无需启动此服务。以 `python3 -B server.py` 启动服务，运营入口在 http://127.0.0.1:8000/admin.html。此前的网页用户端仍保留在 `public/`，当前开发目标为原生 iOS。

## 运营与采集

先将 `YUTO_ADMIN_TOKEN` 配成随机长令牌并重启服务，再打开 http://127.0.0.1:8000/admin.html。管理后台支持查看实库统计、执行日志和来源，管理待执行任务，以及录入和查看景区指标证据，保存后重新计算。

启动独立任务进程：

```sh
python3 -B ingest.py --worker
```

一次性执行也可以直接传入正式公告：

```sh
python3 -B ingest.py --queue https://zwgk.mct.gov.cn/zfxxgkml/zykf/202402/t20240206_951222.html
```

采集器只访问允许列表中的公开正式公告，检查 robots.txt，限制响应体，并在入库时按地点和名称去重。队列支持暂停待处理任务、继续、失败重试和回收过期运行任务。重复采集不会覆盖已经核实的设施证据。

首批资料包含文化和旅游部公开正式公告及目录中 103 个互异景区，来源记录保存在导入文件及内部数据库。覆盖 29 个已有景区记录的省级区划，其余区划可浏览并显示空状态。资料主要核实名称、地区和公布等级，等级、开放状态和设施状况随时间可能变化。景区卡片使用抽象占位图，首页 3D 图为品牌插画。

## 评分与行程

六维权重依次为 25、20、15、15、15、10。每维指标等权，仅采用一致且有证据支持的运营录入值。覆盖率按六维权重汇总。覆盖率达 80% 且每个维度都有证据后才显示总分，缺失指标不会增加得分。个人匹配另按旅行要求计算，关键证据缺失时显示提醒。

目前使用结构化规则分析、关键词和地名识别，以及保守的单城市行程安排。行程以每天至多一个景区为上限。轻松节奏每隔一天保留全天自由活动；页面提示出发前确认开放时间、交通与步行条件。基础等级与银发友好度分别呈现。

## 可选多模态分析

在进程环境配置 `YUTO_MODEL_ENDPOINT`、`YUTO_MODEL_NAME`、`YUTO_MODEL_KEY` 后，运行 `python3 -B intelligence.py 景区ID`。模型接收景区资料、已经核实的指标和最多三张已登记授权的图片。输出仅用于建议用户优先确认哪些条件，评分、设施事实和个性化排除仍来自证据与规则。当前环境未配置模型，也未验证线上调用。景区 ID 可从详情页地址获取。

## 测试与部署

```sh
python3 -B -m unittest -v test_yuto
node --check public/app.js
node --check public/admin.js
```

本地服务默认仅侦听回环地址。部署前请将 `.env.example` 中的配置设置为进程环境变量，放置在提供 HTTPS、请求大小限制和访问控制的反向代理后，为 `YUTO_DB` 配置持久磁盘，并将 Web 进程与采集进程分别托管。可以由主机调度器定期运行一次性采集命令。SQLite 版本适用于单机试运行，公开上线前仍需评估持久化、鉴权及并发要求。

当前缺少完整全国分层排名、持续设施与授权景区实景采集、地图、实时路线和开园校验、真实体验提交审核、跨设备账户以及模型服务配置和线上验收。当前项目按本地交付，未发布线上环境。
